# Req2Web 方案与数据集对应关系

## 方案判断
- 这个方案可行。
- 但“众包代码开发”最好再收紧成“模糊需求到前端原型/网页实现”，这样和现有数据更匹配。
- 你现在的数据更适合做“检索增强 + 提示链编排 + 局部微调”，不适合直接端到端重训一个完整 Agent。

## 更合适的任务定义
- 输入：模糊软件需求、任务说明、截图、草图、界面参考。
- 最终输出：前端页面或 HTML 原型、文本说明、UI 截图和交互流程。
- 内部中间产物：需求拆分、用例列表、开发约束、检索结果和校验结果。
- 核心目标：让 Agent 从“需求理解”走到“界面实现”，并保留可检索的 UI 与流程证据。

## 数据集对应关系

### 需求任务案例库
- Vision2Web 的 Parquet 元数据，以及后续从 frontend / website 任务包中提取的需求说明、PRD 和测试信息
- `Topcoder` 中筛出的 `UI Prototype`、`Responsive Frontend`、`Mobile App Prototype`
- 作用：任务类型判断、需求拆分、约束抽取、验收标准生成

### UI 参考与语义检索库
- `RICO / combined`
- `RICO / semantic_annotations`
- `RICO / rico_semantics`
- `Screen Annotation`
- 作用：检索相似界面、识别控件结构、生成 UI 说明、补齐语义标签

### 交互流程案例库
- `RICO / filtered_traces`
- 作用：生成用户步骤、界面状态变化、storyboard、流程说明

### 视觉原型到实现参考库
- `Design2Code`
- `Design2Code-HARD`
- `Sketch2Code`
- `Vision2Web`
- 作用：生成页面布局约束、前端实现参考、资源使用说明、截图到代码样例

### 开发协作与修复案例库
- `GitHub Issues / PRs`
- 作用：生成异常流程、测试点、验收标准、修复链路参考

## 推荐的 Agent 链
1. 需求理解
2. 用例拆分
3. 任务类型判断
4. UI 检索与语义对齐
5. 流程脚本生成
6. 前端实现约束生成
7. 一致性检查

## 适合做监督微调的节点
- 用例生成节点
- UI 描述生成节点
- 流程脚本生成节点
- 验收标准生成节点

## 不建议直接训练的部分
- 整个 Agent 的规划器
- 工具调用总控
- 全链路端到端策略

## 建议的使用方式
- 基础方案：先用这些数据做检索增强、提示模板和流程编排。
- 增强方案：只对少数文本生成节点做 LoRA 微调。
- 数据分工：把“案例库”和“监督样本库”分开，不要混成一类。

## 一句总结
- 这批数据最适合支撑“输入模糊需求，生成前端实现与 UI 说明”的多模态开发 Agent。

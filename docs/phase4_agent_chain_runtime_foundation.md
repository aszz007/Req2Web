# Req2Web Phase 4 P4-02a Local Graph Runtime Foundation

**Status:** `accepted_local_synthetic_runtime_foundation`

## Scope

P4-02a is a manager-level execution split under the accepted Phase 4 Agent-chain
architecture. It implements only a local deterministic/mock graph foundation.
It does not alter the P4-01 contract packet, the public PageSpec or
ResultPackage contracts, canonical B, D17, G0-G2, the global one-repair rule,
Path 3 non-H1, H1/gold, or the paused C2D authoring state.

The accepted P4-00/P4-01 documentation slice is independently frozen at commit
`01e89c9178593cf8dced1c4e40a0f4bf0072cf7a`, verified equal to remote
`origin/main` before this implementation began.

## Runtime boundary

The direct runtime dependency is fixed in `requirements-phase4-agent.txt` as
`langgraph==1.2.9`. The runtime live-checks that package and the installed
dependency closure before graph construction. The actual local acquisition is
recorded separately in
`docs/phase4_langgraph_dependency_acquisition_receipt.json`, including the
official package index, direct pin, resolved distribution versions, installed
wheel `RECORD` identities, and the acquisition action state. Validation also
recomputes the canonical identity of `requirements-phase4-agent.txt` and checks
every hashed installed file listed by each controlled `RECORD`; missing,
escaping, or drifted files fail closed. A live canonical inventory identity
also covers listed wheel files whose Windows installer rows do not carry a
hash, while generated bytecode is excluded. Every graph run binds the live-
recomputed receipt identity. LangGraph owns only topology
scheduling, update streaming, and in-memory checkpoint mechanics.

Req2Web/Python remains the authority for:

- exact state and record validation;
- canonical JSON identities and replay checks;
- the B/B-Aux boundary;
- stable-ID registration;
- deterministic use-case mappings;
- deterministic composition into the existing `ModelSemanticCandidate`;
- the unchanged canonical PageSpec assembler and its assembly report;
- fail-closed routing and the prohibition on retry or fallback execution.

No Agent Server, Studio, hosted checkpoint service, LangSmith tracing,
telemetry, Provider, model, production route, network connection, or persistent
checkpoint backend is used. `InMemorySaver` evidence is development-process
evidence only; it is not cross-process or durable recovery evidence.

## Fixed synthetic topology

The graph topology is:

```text
canonical deterministic B
-> B-Aux absent/not_requested
-> F1 -> deterministic registry
-> F2 -> deterministic registry
-> F3 -> deterministic registry
-> deterministic use-case mappings
-> F4 -> deterministic registry
-> deterministic candidate projection and canonical reparse
-> existing CanonicalPageSpecAssembler
```

Every F node uses a definition-time deterministic synthetic fixture. B-Aux is
represented by four explicit `absent` consumer dispositions and receives no
stable ID. Mock fixture execution is not a model or Provider call, so every
node result keeps `call_count=0` and the raw-capture sentinel remains
`not_captured` with zero length and the fixed zero digest.

The deterministic candidate projector uses the accepted P4-01 profile: final candidate
`constraints=[]` and `claimed_attribution_edges=[]`. It reparses the canonical
bytes through the existing owning `ModelSemanticCandidate` validator. Its exact
terminal label is `candidate_composition_validated_only`; it does not reuse the
P4-01 `composition_status=composed` success meaning. At that projection point,
the exact field `page_spec_assembler_status_at_projection` remains
`not_executed_p4_02a` and `integrated_success=false`.

The next graph node is a narrow synthetic bridge. It deterministically rebuilds
the same-case local AgentContext and RetrievalGuidance from canonical B, passes
the exact candidate bytes through the unchanged
`CanonicalPageSpecAssembler`, and retains the complete assembled PageSpec and
assembly report with live-recomputed identities. An intentionally mismatched
guidance binding is the fail-closed assembly case. Consistency, Acceptance,
A-07, repair, G0, packaging, and the production route all remain explicitly
`not_executed_p4_02a`; overall `integrated_success=false` remains fixed.

This is assembled graph-foundation evidence only, not Agent, model, downstream
integration, semantic-quality, browser, H1, or formal-quality success.

## Failure and checkpoint rules

- Every graph node can execute at most once in a run.
- Invalid fixture output, identity drift, registry conflict, mapping drift, or
  composition drift stops downstream execution.
- Failure always fixes retry and fallback authorization to false. An assembler
  failure may retain the earlier validated candidate-composition record for
  audit, but it cannot carry assembly success, integrated success, or any
  downstream execution result.
- Streaming is normalized from local graph updates and does not expose a
  second business authority.
- Event type, status, topology, and predecessor identities form a validated
  chain. Each historical `state_audit_identity` is a non-authoritative audit
  correlator; only the current live state/checkpoint validation controls resume
  or success.
- Interrupt/resume requires the same thread, case, request, graph, contract,
  checkpointed-state, and pause-handle identity.
- A wrong or drifted resume handle fails before graph execution.
- Static in-memory pause/resume does not authorize a new model call and does
  not prove restart recovery.

## Action-state truthfulness

The dependency-acquisition receipt records the action that already occurred:

```text
runtime_kind=dependency_acquisition
model_action=false
graph_runtime_execution=false
dependency_installation=true
training=false
remote_action=false
```

Each actual synthetic graph run uses a different exact-key, versioned state:

```text
runtime_kind=local_synthetic_langgraph
model_action=false
graph_runtime_execution=true
dependency_installation=false
training=false
remote_action=false
```

The graph-run state binds the acquisition receipt identity but does not claim
that installation occurred during that run. The accepted P4-01 packet and its
historical bytes remain unchanged with all five P4-01 no-action flags false.

## Verification and stop gate

The only eligible implementation check is:

```powershell
.venv\Scripts\python.exe -m unittest tests.test_phase4_graph
```

The focused tests cover the happy topology, fail-closed downstream freezing,
identity and canonical-byte drift, live registry replay, stable-ID conflict,
exact-key and boolean injection, normalized streaming, in-memory
interrupt/resume, wrong resume binding, tracing rejection, and runtime network
non-use. It also covers direct-requirement and installed-distribution drift,
event-chain tamper, cross-type F1 local-ID conflict, synthetic assembler success
and fail-closed binding mismatch, and unconditional terminal completeness.

Manager review and the same independent exact-diff reviewer closed with
`P0=0`, `P1=0`, and `P2=0`, `accept`, and
`owner_level_adjustment_required=no`. An intermediate focused run exposed three
mechanical test issues; the exact failed cases passed after repair, and the
final complete focused run passed all 20 tests. No broader/full suite, frozen
regression, or model call was run for this slice.

P4-02a is therefore accepted as a local synthetic graph foundation. It does
not automatically authorize P4-02b, Agent Server/Studio, or persistent
checkpoint infrastructure. The project owner has separately authorized a
bounded P4-03 local 9B pilot, but no model call may begin until the P4-03
pre-call D17, runtime-profile, attempt-ledger, and stop-rule records are closed
and independently reviewed. The synthetic assembler bridge in this slice is a
prerequisite; each later real integrated candidate must still pass the same
owning assembler again.
